Tikklabs는 **Hugo로 페이지를 만들고, Blowfish 테마를 적용한 뒤, GitHub Pages에 배포하는 한·영 블로그**입니다. WordPress 사이트를 운영하다 이전했다는 경험담이 아니라, 현재 사용 중인 구성과 그 장단점을 설명하는 운영 기록입니다.

Hugo가 모든 블로그에 더 좋은 선택은 아닙니다. 반복 발행은 자동화할 수 있지만, 테마 변경·배포 오류·검색 설정을 맡아 관리할 사람이 필요합니다. 이 글은 비용과 관리 방식을 비교하고 싶은 개인 블로그 운영자를 위한 안내입니다.

## 현재 블로그는 이렇게 게시됩니다

1. 글과 이미지를 저장소에 반영합니다.
2. GitHub Actions가 Hugo를 실행해 HTML 페이지를 만듭니다.
3. 빌드가 성공하면 GitHub Pages가 완성된 파일을 게시합니다.
4. 운영자는 실제 주소에서 글·이미지·링크가 반영됐는지 확인합니다.

공개 저장소의 글 원본과 홈페이지의 게시 화면은 같은 것이 아닙니다. 원본을 바꿔도 배포가 실패하면 방문자에게는 이전 글이 보일 수 있습니다. 따라서 ‘파일 저장’이 아니라 **실제 페이지 확인**이 게시 작업의 마지막 단계입니다.

![원고 수정부터 실제 홈페이지 확인까지의 게시 흐름](img/editorial/hugo-publish-ko.svg "Tikklabs의 현재 게시 과정을 설명하는 도식입니다.")

## Hugo와 WordPress, 관리 방식의 차이

| 비교 항목 | Hugo + GitHub Pages | WordPress |
|---|---|---|
| 글 작성 | 파일 기반, 편집 도구나 자동화 연결 가능 | 관리자 화면의 편집기 중심 |
| 방문자에게 보내는 페이지 | 미리 만든 정적 파일 | 서버에서 구성하거나 캐시된 페이지 제공 |
| 서버 운영 | 정적 배포 중심 | 호스팅·PHP·데이터베이스 환경 관리 |
| 기능 추가 | 템플릿·외부 서비스·개발 작업이 필요할 수 있음 | 플러그인 등으로 확장 |
| 비용 비교 | 도메인·외부 기능·관리 비용까지 계산 | 호스팅·도메인·유료 기능·관리 비용까지 계산 |

WordPress도 테마와 캐시를 적절히 구성하면 빠르게 운영할 수 있습니다. Hugo를 쓴다고 광고·이미지·자바스크립트의 영향이 사라지는 것도 아닙니다. ‘어느 쪽이 무조건 빠르다’보다 **같은 기능을 넣었을 때의 실제 페이지 성능**을 비교해야 합니다.

## Tikklabs에서 실제로 관리하는 검색 설정

### 1. 배포용 주소와 사이트맵

사이트 설정의 `baseURL`은 실제 도메인 `https://tikklabs.com/`을 사용합니다. 개발용 localhost 주소가 배포된 사이트맵에 들어가지 않도록 확인합니다.

한·영 사이트맵에는 공개 글과 주제별 가이드 등 핵심 페이지를 포함합니다. 태그·카테고리·시리즈·저자 같은 자동 분류 목록은 제외하고, 해당 목록에는 `noindex, follow`를 적용했습니다. 이는 현재 콘텐츠 구성에 맞춘 선택이며 모든 블로그에 필요한 규칙은 아닙니다.

### 2. 서로 대응하는 한·영 페이지 연결

번역 글에는 같은 `translationKey`를 사용합니다. Hugo가 연결된 페이지를 모아 언어 전환 메뉴와 `hreflang` 정보를 만들 수 있도록 하는 표식입니다. 단어를 입력하는 것으로 끝내지 않고 실제 한·영 페이지에 상대 언어 주소가 표시되는지 확인합니다.

`hreflang`은 언어별 대응 페이지를 알리는 정보이지 검색 순위를 올리는 점수나 강제 리디렉션 설정이 아닙니다. `x-default`도 언어·지역에 대응하지 않는 사용자의 기본 페이지를 표시하는 선택 사항이므로, 적용하지 않은 기능을 구현한 것처럼 소개하지 않습니다.

### 3. 내부 링크와 공개 상태

제목을 바꾸더라도 주소를 함부로 바꾸지 않습니다. 글이 `/post/` 아래에 게시된다면 내부 링크에서도 실제 주소를 사용합니다. 숨겨진 초안이나 존재하지 않는 주소로 연결하면 독자는 원하는 설명을 읽지 못합니다.

## 성능과 보안에서 과장하면 안 되는 부분

정적 페이지는 방문 시 데이터베이스에서 본문을 만드는 구성을 줄일 수 있습니다. 그렇다고 해킹 가능성이 없어지는 것은 아닙니다. 저장소 계정·배포 권한·외부 스크립트·사용자 입력을 받는 서비스는 계속 관리해야 합니다.

또한 Lighthouse 점수와 검색 노출은 별개로 확인해야 합니다. Hugo만으로 100점이나 검색 상위를 보장할 수 없습니다. 큰 이미지나 광고를 추가한 뒤에는 실제 모바일 페이지도 다시 살펴보는 편이 좋습니다.

## 이런 운영자에게 맞습니다

글 발행을 파일과 자동화로 관리하고, 댓글·회원 기능보다 정보성 글에 집중한다면 이 구성이 선택지가 될 수 있습니다. 반면 관리자 화면에서 직접 글을 쓰고 여러 편집자·플러그인 기능을 쉽게 관리하려면 WordPress가 더 편할 수 있습니다.

Tikklabs는 원고와 이미지 수정, 빌드, 배포, 실제 페이지 확인을 하나의 게시 작업으로 다룹니다. 도구 이름보다 중요한 것은 **방문자에게 도움이 되는 글을 꾸준히 내보낼 수 있는 관리 방식**입니다.
