온라인 AI 서비스를 사용하다 보면 이미지 한 장을 다시 만들 때도 크레딧이 차감되고, 필요한 달마다 여러 구독을 오가게 됩니다. 그렇다면 반복 작업의 일부를 내 컴퓨터로 옮길 수 있을까요?

이 질문에서 **로컬 AI**가 시작됩니다. 이 글은 프로그램을 바로 설치하기 전에, 로컬 AI가 무엇인지, 실제로 무엇을 얻을 수 있는지, 어떤 작업부터 옮기는 것이 현실적인지를 설명하는 입문 안내서입니다.

## 로컬 AI와 오픈소스 AI는 같은 말이 아닙니다

이 시리즈에서 **로컬 AI**는 AI 모델의 실행과 결과 생성이 내 PC에서 이루어지는 구성을 뜻합니다. 어디에서 실행하느냐를 설명하는 말입니다.

**오픈소스 AI**는 공개 범위와 이용 조건을 설명하는 말입니다. [Open Source Initiative의 정의](https://opensource.org/ai/open-source-ai-definition)에 따르면 사용·연구·수정·공유의 자유와, 시스템을 수정하는 데 필요한 코드·모델 매개변수·학습 데이터 정보 등이 기준에 포함됩니다.

두 표현은 서로 바꿔 쓸 수 없습니다.

| 구분 | 묻는 질문 | 주의할 점 |
|---|---|---|
| 로컬 AI | 모델이 어디에서 실행되는가? | 로컬 앱에서도 외부 API 노드를 선택하면 데이터가 전송될 수 있음 |
| 오픈소스 AI | 무엇을 어떤 조건으로 사용·검토·수정·공유할 수 있는가? | 파일을 무료로 받는다고 모두 오픈소스이거나 상업 이용 가능한 것은 아님 |
| 클라우드 AI | 외부 서버에서 실행되는가? | 설치는 간단할 수 있지만 요금·업로드·서비스 정책의 영향을 받음 |

따라서 Tikklabs는 시리즈 이름으로 **로컬 AI**를 사용합니다. 개별 프로그램과 모델을 다룰 때는 오픈소스 여부와 라이선스를 따로 확인합니다.

![내 PC에서 처리하는 구성과 외부 API를 쓰는 구성의 차이](img/editorial/local-scope-ko.svg "로컬 앱 안에서도 외부 API를 선택하면 입력과 결과가 외부 서비스로 전달될 수 있습니다.")

## 로컬 AI로 얻을 수 있는 네 가지 이득

### 1. 반복 생성의 건별 크레딧을 줄일 수 있습니다

완전히 로컬로 실행되는 단계에서는 이미지를 한 장 더 만든다고 외부 서비스의 생성 크레딧이 차감되지는 않습니다. 썸네일 배경이나 반복 삽화처럼 여러 번 수정하는 작업에서 의미가 있습니다.

다만 무료와 같은 뜻은 아닙니다. 전기, 저장공간, 설치·업데이트 시간, 새 장비를 구입했다면 장비 비용이 남습니다. **이미 가진 PC로 먼저 시험한 경우**와 AI를 위해 새 PC를 산 경우의 경제성은 다르게 계산해야 합니다.

### 2. 제작 과정을 저장하고 다시 사용할 수 있습니다

로컬 제작 도구에서는 모델, 입력값, 해상도, 생성 단계를 작업 흐름으로 저장할 수 있습니다. ComfyUI는 이런 단계를 노드 그래프로 연결하고, 워크플로와 생성 설정을 다시 불러올 수 있도록 설계된 도구입니다.

한 번 성공한 과정을 남겨두면 매번 처음부터 설정할 필요가 없습니다. 하지만 같은 설정이 모든 환경에서 같은 속도와 결과를 보장하지는 않습니다. 사용 모델과 프로그램 버전도 함께 기록해야 합니다.

### 3. 외부 업로드를 줄일 수 있습니다

모델과 입력 자료를 모두 내 PC에 두고, 외부 API를 호출하지 않는 워크플로라면 생성 단계의 자료를 외부 서비스에 업로드하지 않고 처리할 수 있습니다. 개인 자료나 공개 전 콘텐츠를 다룰 때 검토할 가치가 있습니다.

그러나 프로그램이 로컬에 설치됐다는 사실만으로 모든 통신이 사라지는 것은 아닙니다. 모델 다운로드, 업데이트, 클라우드·파트너 노드, 외부 API가 포함됐는지 확인해야 합니다. ComfyUI 공식 저장소도 로컬 실행과 선택적인 API 노드를 구분하며, 코어를 오프라인으로 실행하는 방법을 안내합니다.

### 4. 여러 제작 단계를 연결하고 자동화할 수 있습니다

이미지 생성 후 확대, 배경 제거, 프레임 보정처럼 반복되는 단계를 하나의 워크플로로 구성할 수 있습니다. 작업이 안정되면 같은 과정을 여러 콘텐츠에 재사용하거나 다른 프로그램과 연결할 수 있습니다.

초보자에게는 이 자유도가 곧 복잡함이기도 합니다. 처음부터 긴 자동화 흐름을 만들기보다, **결과물 하나를 직접 만드는 가장 짧은 과정**부터 성공시키는 편이 좋습니다.

## 로컬 AI로 무엇을 만들 수 있을까요

| 제작 영역 | 가능한 작업의 예 | 처음 확인할 것 |
|---|---|---|
| 이미지 | 썸네일 배경, 삽화, 이미지 수정, 확대 | 모델·해상도·VRAM·상업 이용 조건 |
| 영상 | 이미지의 짧은 움직임, 짧은 클립, 프레임 보간 | 처리 시간·저장공간·모델 요구 사양 |
| 음성·TTS | 문장을 음성으로 변환, 로컬 내레이션 제작 | 한국어 품질·음성 권리·모델과 출력물 라이선스 |
| 텍스트·LLM | 초안, 요약, 분류, 개인 문서 질의 | 모델 크기·정확성·문서 보안·상업 이용 조건 |

[ComfyUI 공식 프로젝트](https://github.com/Comfy-Org/ComfyUI)는 노드 그래프로 이미지·영상·오디오·3D·텍스트 작업을 구성할 수 있다고 설명합니다. 그렇다고 모든 영역을 ComfyUI 하나로 시작해야 하는 것은 아닙니다.

Tikklabs에서는 **ComfyUI를 이미지·영상 제작의 중심 도구**로 다룹니다. TTS는 ComfyUI 확장 워크플로와 별도 음성 프로그램을 모두 비교해, 초보자가 더 쉽게 재현할 수 있는 경로를 선택합니다. 로컬 LLM도 별도의 도구와 모델 선택이 필요합니다.

## ComfyUI는 무엇인가요

ComfyUI는 생성 단계를 상자 모양의 **노드**로 만들고 선으로 연결하는 제작 도구입니다. 예를 들어 이미지 생성에서는 대략 다음과 같은 흐름이 구성됩니다.

> 모델 불러오기 → 문장 입력 → 빈 이미지 크기 결정 → 생성 → 이미지 저장

일반 앱이 여러 설정을 메뉴 안에 숨긴다면, ComfyUI는 작업 과정을 화면 위에 펼쳐 보여줍니다. 처음에는 복잡해 보이지만, 어느 모델과 설정이 결과에 연결되는지 확인하고 같은 흐름을 재사용하기 좋습니다.

ComfyUI 자체와 생성 모델은 별개입니다. **ComfyUI는 작업을 연결하고 실행하는 도구이고, SDXL 같은 체크포인트는 실제 생성에 사용하는 모델 파일**입니다. ComfyUI를 설치했어도 필요한 모델이 자동으로 모두 준비되는 것은 아닙니다.

## 누구에게 로컬 AI가 맞을까요

다음에 해당하면 보유 PC에서 작은 시험을 해볼 가치가 있습니다.

- 같은 종류의 이미지나 음성을 반복해서 만듭니다.
- 생성 횟수가 늘어 크레딧이나 월 구독이 부담됩니다.
- 작업 흐름을 직접 조정하고 다시 사용하고 싶습니다.
- 공개 전 자료를 외부 서비스에 올리는 범위를 줄이고 싶습니다.
- 설치와 오류 해결에 약간의 시간을 쓸 수 있습니다.

반대로 사용량이 적고 설정에 시간을 쓰기 어렵거나, 최신 온라인 모델의 결과가 즉시 필요하다면 필요한 달만 구독하는 편이 더 경제적일 수 있습니다. 로컬과 클라우드를 함께 쓰는 것도 실패가 아닙니다. 반복되는 부분만 로컬로 옮겨도 됩니다.

## 장비를 사기 전에 이렇게 시작하세요

1. **결과물을 하나 정합니다.** 예: 블로그 썸네일용 배경 이미지 한 장.
2. **현재 PC에서 시험합니다.** 설치 가능 여부와 실제 모델 실행 가능 여부를 구분합니다.
3. **가장 단순한 공식 워크플로를 사용합니다.** 처음에는 커스텀 노드와 여러 모델을 한꺼번에 추가하지 않습니다.
4. **한 장을 완성하는 데 든 시간을 기록합니다.** 생성 시간뿐 아니라 수정과 오류 해결 시간도 포함합니다.
5. **온라인 서비스의 같은 작업과 비교합니다.** 품질·시간·비용 중 무엇이 나아졌는지 확인한 뒤 구독이나 장비 구매를 결정합니다.

그래픽카드의 이름이나 VRAM 숫자만으로 모든 로컬 AI 작업을 가능·불가능으로 단정할 수 없습니다. 이미지와 영상, 사용하는 모델, 해상도, 동시 생성 수에 따라 요구 조건이 달라집니다. Tikklabs의 실습 글에서는 실제로 사용한 환경과 모델을 함께 기록합니다.

아직 공개하지 않은 항목은 깨진 링크 대신 **준비 중**으로 표시합니다. 실제 실행과 검증이 끝난 글부터 연결합니다.

이 시리즈는 문서만 재구성한 사용기를 만들지 않습니다. 처음 사용하는 사람이 실제로 따라가며 막힌 지점, 해결 과정, 완성된 결과를 확인한 뒤 글에 반영합니다.
