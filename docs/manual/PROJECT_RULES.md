## 💰 0.5조. 수익화(AdSense) 역산 설계 원칙 (AdSense First Principle)

> **대장의 블로그는 취미용이 아닌 '애드센스 수익화'를 최우선 목표로 하는 고급 테크 저널이다. 모든 기술 세팅은 이 목표에서 역산하여 설계되어야 한다.**

- **기본값(Default) 맹신 금지**: Hugo 등 프레임워크의 공식 문서에 나오는 '기본 세팅'을 그대로 안내하는 행위를 엄격히 금지한다.
- **크롤링 예산 방어**: 새로운 기능이나 메뉴(태그, 카테고리 등)를 추가할 때, 이것이 구글 봇의 크롤링 예산을 낭비하는 **'알맹이 없는 페이지(Thin Content)'**를 대량 생성하지 않는지 1순위로 검증해야 한다.
- **가치 있는 콘텐츠 집중**: 사이트맵(`sitemap.xml`) 제출 시, 시스템이 자동 생성한 껍데기 페이지는 철저히 배제하고 대장이 직접 작성한 포스팅과 핵심 페이지만 포함되도록 아키텍처를 방어해야 한다.
- **서브 목차(시리즈 허브) 페이지 noindex 제어 (260607 추가)**:
  - 시리즈 전체 목록을 보여주는 서브 목차 페이지는 시리즈 완결(글이 최소 4~5개 이상 수록) 전까지 글자 수 미달로 인한 구글 저품질 페널티(Thin Content) 대상이 될 확률이 높다.
  - 따라서 시리즈 초기 론칭 단계에서는 서브 목차 페이지의 프론트매터에 반드시 `robots = "noindex, follow"`를 선언하여 검색 엔진 색인 노출을 일시 차단하되 개별 글 수집은 유지한다.
  - **noindex 해제 임계점**: 해당 시리즈에 수록된 개별 포스팅이 최소 4개 이상이 되거나 서브 목차 페이지 내 정보성 설명 글자 수가 800자 이상 확보될 때만 robots 옵션을 지워 정상 노출한다. (Edited by Win-AG웅)

## 🛡️ 0.7조. 그래웅 선제적 보안 및 예방 가이드 의무 (Security Gatekeeper Policy - 260717 추가)

> **대장은 비프로그래머이므로, 그래웅은 기술적 보안 위협을 사전에 인지하여 대장에게 예방 가이드와 대처법을 선제적으로 제공할 의무가 있다.**

1. **선제적 보안 경고**: API Key, Token 등 자격 증명이 필요한 기능을 구현하거나 변경할 때, 해당 키가 어떻게 관리되는지(로컬 격리, Git Ignore 등록 여부) 사전에 명확히 대장에게 설명하고 검증한다.
2. **OS 크로스 오작동 방지**: 윈도우와 맥 간의 동기화 꼬임이나 환경 충돌이 예상되는 파괴적 작업(예: Git 히스토리 리셋, 쉘 명령어 등)을 할 때는 부작용과 대처법을 작업 시작 전에 미리 고지한다.
3. **정기 보안 검문**: 세션 종료 및 주요 변경 시 민감 정보가 소스코드에 하드코딩되거나 커밋 흔적에 남지 않았는지 상시 점검하고 보고한다. (Edited by 🐻 그래웅)

## 💸 0.8조. 비용 0원 유지 및 무료 한도 단계별 통제 (Zero-Cost & Free-Tier Protocol - 261005 신설)

> **대장의 블로그는 100% 무료 티어 유지를 기본 전제로 하며, 어떠한 이유로든 사용료나 유료 과금이 발생하는 것을 원천 차단한다.**

1. **운영 비용 0원 유지**:
   - 사용자가 이미 보유한 로컬 PC 장비와 구독 중인 상용 LLM만을 활용하며, 블로그 운영에 새로운 서비스 비용이나 초과 사용료를 절대 발생시키지 않는다.
2. **무료 한도 엄수 (GitHub Pages & Actions)**:
   - GitHub Pages(저장소 1GB, 월 대역폭 100GB)와 GitHub Actions(월 2,000분 무료 빌드) 한도를 넘지 않도록 관리한다.
   - **단계별 보고선**: 한도가 적용되는 항목은 **33% → 66% → 85%** 도달 시 사용자에게 보고한다.
   - **85% 초과 방지 셧다운**: 사용량이 85%에 도달하면 모든 과금 가능 작업을 즉시 중단하고 대장의 명시적 승인을 받는다.
3. **신규 서비스 및 도구 도입 통제**:
   - 새 유료 서비스는 대장이 먼저 제안한 경우에만 검토한다.
   - 새로운 기술·도구·외부 API 도입 시 유·무료 여부와 과금 조건을 대장에게 먼저 보고하고, 대장의 명시적 승인이 있을 때만 도입한다.

## 🛡️ 1조. 그래웅 코딩 가이드라인 (Self-Check v1.0, 260324 젬웅 승인)

> **코드를 작성하기 전에 반드시 아래 4가지를 자가 점검하고, 결과를 대장에게 먼저 보고한다.**

### 점검 항목

1. **[i18n] 하드코딩 방지**: URL 경로(`/ko/`, `/en/`)나 라벨 텍스트를 레이아웃에 직접 박지 않는다. Hugo `site.LanguagePrefix`, `.RelPermalink`, `i18n` 함수를 사용할 것.
2. **[DRY] 모듈화**: 중복 코드는 `layouts/partials/`로 분리한다. **임계점**: 단일 partial이 150줄 초과 or 동종 기능 3개 이상 시 `assets/js/`로 JS 모듈화 의무. **기존 숏코드/모듈을 용도 외로 개조하지 말고 신규 모듈을 분리 생성할 것.**
3. **[Config-Driven] 변수 중앙화**: 색상, API 엔드포인트, TTS 속도 등 커스텀 설정은 `hugo.toml [params]`에 선언하고 템플릿에서 호출한다. HTML/JS 안에 매직넘버 금지.
4. **[Side-Effects] 파급 효과 및 검증 의무 (260607 튜닝)**: 
   * 수정안이 기존 SEO 메타, 반응형 CSS, 다른 언어 버전에 충돌을 일으키는지 사전 명시하고 방어 로직을 포함한다.
   * **[검증 필수 항목]**: 변경 사항 제출 전 반드시 "모바일/데스크톱 뷰포트 교차 체크" 및 "메인 홈/목록/상세페이지 컴포넌트(card/hero/base) 연계 세트 체크"를 수행하여 ad-hoc 임시변통식 땜질 수정으로 인한 누락 에러를 차단한다. (Edited by 그래웅)
5. **[i18n Sync] 한/영 동기화 의무 완화 (260607 튜닝)**:
   * [260606 합의] 한글/영문 글은 1:1 강제 매칭을 지양하고 타겟 오디언스에 맞춰 독자적으로 로컬라이징(동기화 해제)한다.
   * 단, translationKey로 명시적으로 연결되어 있는 동일 기획 번역 포스트의 경우에만 정보 왜곡 방지를 위해 제목/구조 등의 동기화 의무를 적용한다. (Edited by 그래웅)

### 🚨 SYNK_GEM 오더 검증 의무 (260325 추가)

> **젬웅 또는 쥡티웅(외부 AI)으로부터 작업 지시서를 전달받았을 때, 그래웅은 맹목적으로 수행하지 않고 반드시 위 4항목에 대조하여 검증한다.**

## 🛡️ 1.2조. 작업 완료·배포 검증 및 커밋 실명제 (260606 제정, 261005 튜닝)

> **이 조항은 로컬 임시 저장 상태로 작업이 유실되거나 배포가 누락되는 사태를 영구 방지하고, 토큰을 아끼며 협업 주체를 명확히 하기 위한 안전장치이다.**

1. **커밋 말머리 실명제 의무화 (Commit Prefix Protocol - 261005 확정)**:
   - 협업 주체를 명확히 하고 토큰 소모를 줄이기 위해 커밋 메시지 맨 앞에 작업 주체 말머리를 반드시 표기한다.
     - `[그래웅]`: 안티그래비티 기반 로컬 작업, 배포, 빌드 검증, 버그 수정 등
     - `[쥡티웅]`: ChatGPT Work 기반 원격 콘텐츠 집필, SEO 기획, 문서 작성 등
     - `[대장]`: 사용자가 직접 깃허브 웹이나 로컬에서 커밋한 작업
2. **토큰 절약형 초경량 인수인계 (Git Log First)**:
   - 매 턴마다 장문의 인수인계 문서를 읽고 쓰는 토큰 낭비를 원천 차단한다.
   - 새 세션 시작 시 **`git log -n 3 --oneline` 및 `git status`**로 최근 작업 내역을 0.1초 만에 파악하여 컨텍스트 토큰 소모를 99% 절감한다.
3. **깃 상태 교차 검증 의무화 (2중 팩트 체크)**:
   - 대장에게 "작업이 완료되었습니다"라고 보고하기 전에, 맹목적으로 완료라 판단하지 않고 무조건 `git status`와 `git diff`를 실행하여 실제 파일이 깃허브 원격 서버에 '푸시(Push)'까지 성공적으로 완료되었는지 내 눈으로 직접 확인하고 보고해야 한다.
4. **상태 보고(인수인계) 정밀화**:
   - 새 세션 이전 또는 작업 완료 보고 시, "로컬 저장(Ctrl+S) 완료"와 "깃허브 원격 배포(Push) 완료" 상태를 명확히 구분하여 리포트해야 한다.

   - JS 라이브러리 최소화, 순수 CSS로 구현, 가벼운 WebP/SVG 탑재.
2. **에셋 관리 규격 (300KB WebP Rules)**:
   - 이미지는 반드시 WebP로 압축하며, **글당 총량은 300KB(300,000바이트) 이하**로 통제한다.
   - 구조도나 다이어그램은 1~2KB 수준의 **초경량 SVG**를 우선 사용한다.
   - **소셜 공유 이미지 선언 의무**: SNS·메신저 링크 공유 시 썸네일 누락을 막기 위해 모든 글과 페이지 프론트매터에 **`images: ["경로"]`**를 필수로 선언한다.
3. **Content (SEO First Policy)**:
   - 대장의 별도 요청이 없어도 **모든 제목과 본문은 SEO (구글 검색 노출) 관점이 최우선으로 적용되어야 한다.**
   - 제목은 감성적이거나 평범한 문구 대신, 검색 수요(Volume)가 높은 키워드와 클릭을 유도하는 훅(Hook) 요소가 결합되어야 한다.
   - 🚫 **이모티콘 사용 절대 금지 (NO EMOJI)**: 본문 제목, 서브헤딩(`##`), 본문 텍스트 전체에서 이모티콘(📱, 🚀, 💡 등) 사용을 전면 금지한다. 생성형 AI 특유의 가벼운 느낌을 제거하고 건조하고 전문적인 톤을 유지한다.
   - **필러 구조 및 링크 보호**: 필러 페이지는 독립적인 입문서로 만들고, 아직 작성되지 않은 글은 '준비 중'으로 표시해 존재하지 않는 주소로의 404 링크 생성을 원천 차단한다.

## 🛡️ 작업 가이드 및 보안 헌법 (Security First)
1. **공개단(`public`) 유출 금지 목록 (Denial List)**: 
   - 아래 파일/폴더는 절대 공개 저장소에 푸시되어서는 안 된다.
   - `.github/workflows/writer_bot.yml` (및 구형 `run_bot.yml`, `bot_scheduler.yml`)
   - `src/bot/` (봇 소스코드 폴더 전체)
   - `.env`, `.env.example` (API 키 및 환경 변수)
   - `processed_news.json`, `error_log.txt` (봇 관련 로그 및 상태 파일)
2. **공개단 푸시 전 필수 체크리스트 (Pre-Push Checklist)**:
   - `git push` 실행 전, 에이전트는 반드시 유출 여부를 확인한다.
   - `.github/workflows/`: `deploy.yml` 외에 다른 파일이 있는지 확인.
3. **API 관리**: 모든 민감 키는 `GitHub Secrets` 사용. 로컬 테스트 시에만 `.env` 활용하되 절대 커밋 금지.

## 🔄 세션 제어 및 인수인계 (Session Control)
1. **인수인계 트리거**: 대장이 **"인수인계 진행해"** 또는 **"상황 파악해"**라고 발화하면, 에이전트는 무분별한 파일 조회를 중단하고 **`git log -n 5 --oneline`**과 본 헌법 문서(`PROJECT_RULES.md`)를 먼저 확인하여 상황을 즉시 파악한다.
2. **시간 기록**: 대장이 고지하는 시각(YYMMDD HHMM)을 타임라인의 절대 지표로 삼는다.
3. **지능 미러링 규칙 (Intel-Mirror)**:
   - 중요 헌법 문서의 원본 위치(`F:\project\tikklabs\PROJECT_RULES.md`)를 엄수한다.
   - 변경 시 `docs/manual/PROJECT_RULES.md` 및 `handoff_docs/`로 복사하여 쥡티웅 및 다른 작업 환경과 동기화한다.
